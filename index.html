Project 01 · Engine

Umapyoi Engine

A custom game engine written in C++ by a team of eight over seven months, with ImGui-based editor tools. My parts were the math library, the event system, the UI and the editor gizmo.

  • C++
  • ImGui
  • 8 people
  • 7 months
  • Math lib · Events · UI · Gizmo
  1. 01Problem

    The course required us to build our own engine instead of using an existing one, so every system a game needs had to be written by the team.

  2. 04What failed

    The editor gizmo didn't handle every object the same way. Transform components (game objects) and RectTransform components (UI elements) behave differently, so a gizmo that worked for one didn't work properly for the other.

  3. 06What happened

    We used the engine to build and ship Parry Everything, which was nominated to be presented at a school event.

Project 02 · Game

Parry Everything

A game built on our own Umapyoi Engine. A 2D roguelite built around timing-based parries.

  • Umapyoi Engine
  • C++
  • Nominated for a school event
  1. 01Problem

    Parrying is the whole game, so it had to feel fair and responsive. If players miss a parry, it should be because of their timing, not the controls.

  2. 04What failed

    Players struggled with the controls. Juggling mouse buttons and key combinations at once got in the way of the parry timing.

  3. 05What changed

    We switched to Q, E and R combinations only, so players could focus on one action per hand.

Project 03 · Tool

AnytimeReno

A floor plan editor for renovation planning that runs in the browser, where users draw walls and rooms, measure them and place furniture. Built in Unity 6.3 for WebGL as a team project. I own the UI, the measurement overlay and the scene saving system.

  • Unity 6.3
  • C#
  • WebGL
  • Team project
  • UI · Measurements · Saving
  1. 01Problem

    Users needed to lay out walls and rooms themselves, in the browser, while the app was running. That meant a runtime authoring tool, not a Unity Editor extension, with a UI that could keep growing as the team added tools like image import and furniture upload.

  2. 04What failed

    Selecting a second wall stacked a second set of Length and Height fields under the first in the inspector, because the panel was hidden and shown again without clearing its rows.

    The mode buttons also stayed lit after a wall was placed, since nothing told the UI that the editor had gone back to its default mode.

  3. 05What changed
    • The inspector now clears its rows before rebuilding, and UIManager watches the editor's mode so buttons switch themselves off.
    • I moved saving to snapshot-only, storing corners and the walls between them, so a load never has to replay a chain of changes. The file format still has room for incremental saves later.
    • Each save is hashed and points to the save before it, so the system can check a file is intact and spot two tabs saving over each other.
